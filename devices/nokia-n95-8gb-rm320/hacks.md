# Nokia N95 8GB (RM-320): device hacks

The workarounds that belong to this device: its hardware stand-ins, its ROM configuration and the
byte patches of its own code. Platform-wide ones (kernel, QEMU, board, sydb) are in
[docs/hacks.md](../../docs/hacks.md); hack ids are the same in both.

## ROM / configuration (devices/nokia-n95-8gb-rm320, tools/device.py build)

| Hack | Real implementation |
|---|---|
| `Z:\sys\data\ESTARTCOMP.TXT` replaced: D: = local drive 0 (IRAM), C: = 1 (NVMemory, 64 MB FAT16), E: = 2 (second NVMemory, memory card, 1 GB FAT32), Z: = composite with ROFS on 8; no Y: | fine; drive images are persistent with `scripts/run-gui.sh` (build/n95/drive-c.img, drive-e.img), host access with `scripts/n95-drive.sh` (mtools) |
| N95 kernel side dropped wholesale; our kernel files placed below the N95 user window | n/a |
| Paging off: the core ROM is flattened | n/a |
| **H-gles-blob:** our GLES/EGL code (`src/sygl`, built by `src/sygl/build.sh`) is a raw prelinked blob at 0x80320000 (`romcompose.py --blob`), in the gap between our listed files and the N95 user side (holds only our dead user-side files; the composer refuses an overlap). No loader, no import table, no writable static data (linker assert); N95 functions are called at their export addresses (`n95imports.txt` → generated header). Included by `hybrid-boot.sh` when `build/devices/<id>/sygl/sygl.bin` exists (`SYGL=0` leaves it out) | a real `libgles_cm.dll` replacement would have to keep all 175 export addresses anyway (ROM importers are bound to them); a loadable DLL needs loader support for an XIP DLL we add |

## User-side code patches (devices/nokia-n95-8gb-rm320/code-patches.txt, tagged [H-...])

Byte patches on N95 binaries in the composed ROM; original bytes are verified at compose time.

| Hack | Where | Real implementation |
|---|---|---|
| **H-keysound-nommf:** `blx CMdaAudioToneUtility::NewL` → `movs r0,#0; nop` (2 sites) so the key-sound server keeps a NULL tone player instead of leaving −1 when MMFAudioServer cannot start (no DSP) | `eiksrvui.dll` 0x82f0e366, 0x82f0e9c8 | working audio (MMF with a fake DSP/DevSound). Risk: the tone player's prepare-complete callback dereferences without a check, but it is only invoked by a live player; key tones are silent |
| **H-startuptone-nommf:** `blx CMdaAudioPlayerUtility::NewFilePlayerL` → `movs r0,#0; nop` in `CStartupTone::ConstructL`: no startup-tone player (opening it blocked Startup's main thread in a synchronous MMF call → `ViewSrv 11` after 10 s); `Play()` returns `KErrNotReady` and Startup falls back to a (silent) key sound | `startup.exe` 0x833a93c4; analysis in `docs/devices/nokia-n95-8gb-rm320/n95-startup-animation.md` | working audio |
| H-keysound-nommf (continued): the two tone-play helpers return at once (`bx lr`) | `eiksrvui.dll` 0x82f0ea94, 0x82f0eac8 | working audio |
| **H-gles-present:** window surfaces are presented by direct screen access (`RDirectScreenAccess` in a small active object, `src/sygl/plat.cpp`): sygl copies only the visible region's rectangles into the frame buffer. On the N95, WSERV's abort goes into a message queue that ws32's own priority-2000 active object services; for apps that never yield to their scheduler (ZigGLTri drains WSERV events itself) each swap runs only the ready DSA-priority active objects (`CActiveScheduler::RunIfReady(.., 2000)` + one `WaitForAnyRequest` each), then acknowledges with `Completed()` and requests the new region. Verified 2026-11-06: Menu over ZigGLTri gives 0 rects (menu stays clean), back in front 1 rect, the task switcher popup leaves 2 rects around it. Without a CONE environment or an active scheduler: direct copy of the whole window (no clipping) | `src/sygl/plat.cpp`, `egl.c` `sy_present` | running other apps' high-priority objects from eglSwapBuffers is our addition (a Symbian app is expected to yield); fine as long as only DSA-priority objects are run |
| **H-gles-window-fixed:** window surfaces keep the size and position their window had at eglCreateWindowSurface; resizes and rotations are not followed (eglQuerySurface keeps answering the creation size, present blits at the creation position clipped to the DSA region). This is what the N95's own `libpvrTechviewWSEGL.dll` does (window Size/AbsPosition read only at creation, docs/gpu-roadmap.md "Fidelity"); the owner saw ZigGLTri off-centre after a landscape switch on the real phone. Replaces the 2026-11-06 follow mode (removed on the owner's call: compatibility, not imitation). Known gap: Carousel after a landscape switch now draws its 240x320 surface at (0,0) of the landscape screen, part of the screen stays unpainted; on the device it works, so the real driver has a mechanism we do not model yet (lead: WSEGL's rotation field, native-orientation buffers rotated by the pvr2d blit) | `src/sygl/egl.c` | Carousel landscape is wrong until that is found |
| **H-gles-host:** GLES rasterisation on the host GPU. sygl keeps the whole GLES 1.1 state machine, transform, lighting, clipping and EGL rules; its rasteriser input (window-space triangles + raster state, clears, texture images in row bands, read-backs) goes as a command stream (`src/qemu-syborg/hw/arm/syborg_gl_proto.h`) through DisplayDriver controls 0x7f10/0x7f11 (our d_display stand-in copies it into 1 MB of contiguous RAM) to the `syborg-gl` QEMU device (0xc000f000), which runs it synchronously on a surfaceless EGL/GLES 2 context (one FBO per window/pbuffer surface; pixmaps stay in software) and reads frames back at swap, glReadPixels, CopyTex and eglBindTexImage. Ids are scoped by the guest thread (SYGL_OWNER); eglTerminate frees them. Default on; `sydb start/phone --gl soft`, `GL=soft scripts/run-gui.sh` or `-global syborg-gl.backend=off` give the software rasteriser; no host EGL also falls back. Verified 2026-11-06 on radeonsi (Mesa 26.2.5): Carousel renders fully; Crash Bandicoot Nitro Kart 3D menus and races at 60 fps (vsync cap; software: ~19/~11) | `src/sygl/hw.c`, `src/qemu-syborg/hw/arm/syborg_gl.c`, `src/standins/d_display/d_display.cpp` | GL objects are not migrated: after a snapshot restore the host has none of the guest's surfaces/textures until it recreates them; colour interpolation is perspective-correct on the host |
| **H-kernel-abi-92:** third-party kernel drivers (LDD/PDD from C:/E:) are built for the N95's own 9.2 kernel. `tools/personality/kabi.py` compares its exported driver-facing vtables (DObject, DLogicalDevice, DPhysicalDevice, DLogicalChannelBase, DLogicalChannel, DPowerHandler, read from build/n95/core-flat.img) with ours slot by slot; `--func NAME` disassembles an export from both (the DObject/DLogicalChannel constructors show the same data layout, iObjectId included). Our kernel differed only in two DObject virtuals (`RequestUserHandle(.., TUint)`, `AddToProcess(.., TUint)`, now non-virtual: only flexible/win32 shared buffers overrode them) and DLogicalChannel::SendMsg (now declared after HandleMsg; `DLogicalChannel::Request` calls it non-virtually for RAM-loaded drivers, which have no such slot). Also no user memory guards (debug kernels deny supervisor access to user memory; the N95's release kernel allows it and 9.2 drivers rely on it). Verified 2026-11-06: kabi92 reports all six classes identical (DLogicalChannel plus our appended SendMsg); RomPatcher+ on a copy of the owner's device loads patcherShadow.ldd, lists its patches and applies Install Server RP+. Before: the phone froze in the crash monitor | `personalities/sym92/patches/0008-n95-kernel-abi-92-drivers.patch`, `0009-n95-no-user-memory-guards.patch`, `tools/personality/kabi.py` | drivers that need Nokia/OMAP kernel parts still will not work; other exported kernel classes are not compared yet |
| **H-modem-power:** the fake modem (iscpeer.inl) answers MTC_POWER_OFF_REQ (0x03) / MTC_RESET_GENERATE_REQ (0x06) and 3 s later switches the machine off / resets it through the Syborg platform device's POWER register (word 2: 1 off, 2 reset; QEMU shutdown/reset request). On a BB5 phone the modem owns the power supply and cuts it while the application side shuts down; before this, the phone showed the goodbye animation and then kept running (even the screensaver came back). Verified 2026-11-06: Power menu > Switch off! ends QEMU, the sydb session and the phone window | `src/standins/stubs/iscpeer.inl`, `src/qemu-syborg/hw/arm/syborg.c` | the 3 s grace period is ours (the real modem's timing is unknown) |
| **H-gles-identity:** sygl reports the N95's own driver strings (GL_VENDOR "Nokia", GL_RENDERER "1.2.19.1 HW PowerVR MBX with VGP", GL_VERSION "OpenGL ES-CM 1.1", EGL_VENDOR "Imagination Technologies", EGL_VERSION "1.1 build 3.3.33.750.2", read from libgles_cm/libimgegl in the ROM), because apps choose their render path by them (Crash Bandicoot Nitro Kart 3D falls back to its own software renderer otherwise). GL_EXTENSIONS lists only what sygl implements | `src/sygl/gl.c`, `egl.c` | n/a (identity of the device being emulated) |
| **H-gles-trampolines:** the first word of each of the 175 `libgles_cm.dll` entry points → `b` into the blob's entry table (slot = ordinal); generated into `devices/<id>/gl/gles-patches.txt` by `tools/gen-gles-glue.py`, applied only together with H-gles-blob. Nokia's PowerVR path (libimgegl, services_um, the missing `services.ldd`) is never entered.
