# Fake-modem canned replies of the N73 (RM-132), started as a copy of the N95 8GB's (docs/adding-a-device.md
# step 4: they are per ISI resource, not per phone); each is re-checked against the N73's requests
# in the boot log (tools/isi.py log). Names: platform/isi/names.txt.
# Layered on platform/isi/replies-bb5.txt (shared replies); tools/isi.py gen-header turns both into
# build/devices/<id>/gen/isireplies.h.
# NET_MODEM_REG_STATUS (0A 00) deliberately unanswered: the proposed reply made NOKIATSY panic
# "IsiMessage: OFFS -9" (subblock shorter than its parser expects); nothing waits for it.
# 17 0A: SAEmService op 1 = battery bars (sb 0x16: [2]=7 max, [3]=1..7), op 2 = charger (sb 0x15:
# [2]=1 not charging); NOKIATSY reads sb 0x16 too. Both sent (hack H-em).
# N73 (NokiaDSY SIM start-up, DOS request 806): PN_SIM 0x3B "FA 00" = IMSI-equal query; resp 0x3C
# {service FA, cause 2A = IMSI equal}; without it start-up stays at system state 202
# (docs/devices/nokia-n73-rm132/isi-sim-3b.md)
reply 09 3B 3C FA 2A
# N73 NOKIATSY: product profile read in the older numbering (INFO_PP_READ 0x02/0x03; the N95 uses
# 0x29/0x2A, answered by echoing its sub-blocks). Echo of the one request seen (sub-block 0x47, feature
# 0x01, value 0 = off). Unanswered, it kept DosServer blocked in ETel (custom request 1000019), so
# DosServer never read the SIM channel and start-up stayed at system state 202.
reply 1B 02 03 00 01 47 08 00 01 01 00 00 00
# N73 NOKIATSY SIM requests after the product profile [inferred]: no SIM, so "service, 0x24 = data not
# available" as the N95 accepts for READ_IMSI 0x1D / language 0x1F (response id = request id + 1)
reply 09 29 2A 35 24
reply 09 31 32 3B 24
