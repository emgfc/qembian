# Fake-modem canned replies of the 5730 (RM-465), started as a copy of the N95 8GB's (per ISI resource,
# not per phone). Names: platform/isi/names.txt.
# Layered on platform/isi/replies-bb5.txt (shared replies); tools/isi.py gen-header turns both into
# build/devices/<id>/gen/isireplies.h.
# NET_MODEM_REG_STATUS (0A 00) deliberately unanswered: the proposed reply made NOKIATSY panic
# "IsiMessage: OFFS -9" (subblock shorter than its parser expects); nothing waits for it.
# 17 0A: SAEmService op 1 = battery bars (sb 0x16: [2]=7 max, [3]=1..7), op 2 = charger (sb 0x15:
# [2]=1 not charging); NOKIATSY reads sb 0x16 too. Both sent (hack H-em).
# 5730 (RAPIDO audio): MmfAudioServer's DSP control server asks resource 0xF3 msg 0x30 (header only) and
# waits for 0x31 with 34 bytes {2 unread, A0..A3, B0..B3 as u32}; nothing is validated, zeros = no DSP
# memory to map (docs/devices/nokia-5730-rm465/rapido-audio.md). Without it start-up times out.
reply F3 30 31 len=34
# 5730 playback-time DSP requests, silent (docs/devices/nokia-5730-rm465/rapido-audio.md "Playback
# requests (silent)"): each request is ctl 8 -> 0x32/0x33 -> 0x3B/0x3C; no status is checked, but Aamm
# panics on a sample-rate code outside {2,4,8,..,0x200,0x800,0x1000} (0x33 @14) [V]
reply F3 32 33 00 00 00 02 02 00
reply F3 3B 3C 00 00 00 00
# other commands, same pattern [inferred]
reply F3 3D 3E 00 00 00 00
reply F3 3F 40 00 00
reply F3 41 42 00 00
# 5730 TSY: PN_SIM 0x62 {4D 01 01} after ETel request 40018 (ConnMon, then DosServer's SAE thread wait on
