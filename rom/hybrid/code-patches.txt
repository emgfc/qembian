# Byte patches applied to the composed hybrid ROM by tools/romcompose.py --patches.
# Format: ADDR  ORIGINAL-BYTES  NEW-BYTES  # reason (bytes in memory order; Thumb halfwords are LE)
# Every entry is a hack listed in docs/hacks.md.

# H-keysound-nommf: eiksrvui.dll key-sound server creates CMdaAudioToneUtility (MMF) for each tone
# sound; without the DSP bridge MMFAudioServer cannot start, NewL leaves -1, EikSrvs dies and the
# Avkon chain restarts forever. Replace "blx CMdaAudioToneUtility::NewL" with "movs r0,#0; nop":
# tone player stays NULL (the play paths check it). Key tones are silent.
82f0e366  01f0a2eb  0020c046   # eiksrvui.dll+? sound-info ConstructL
82f0e9c8  01f070e8  0020c046   # eiksrvui.dll re-create on prepare

# H-splash-behind: SplashScreen.exe puts its window group at ordinal priority 1001 (above every
# window) and only drops to -1000 when its 120 s timer expires; Starter then restarts it while the
# startup sequence is unfinished, so it covers the screen forever (and its SVG logo renders empty).
# Patch the literal 1001 -> -1000 so the splash is a bottom-most background and the startup UI
# (notes, queries, idle) shows above it.
833a6574  e9030000  18fcffff   # SplashScreen.exe window-group priority literal

# H-keysound-nommf (continued): the two tone "play" helpers dereference the (NULL) tone player
# without a check (EikSrvs KeySoundServer KERN-EXEC 3 on the first key/notification tone).
# Make them return at once.
82f0ea94  c169  7047   # eiksrvui.dll tone play helper 1: ldr r1,[r0,#28] -> bx lr
82f0eac8  c169  7047   # eiksrvui.dll tone play helper 2: ldr r1,[r0,#28] -> bx lr

# H-startuptone-nommf (docs/n95-startup-animation.md): Startup.exe CStartupTone::ConstructL creates a
# CMdaAudioPlayerUtility for the startup tone; without the DSP bridge the MMF open blocks the main
# thread in a synchronous controller call, the view server times out (ViewSrv 11, 10 s) and the
# welcome animation is never shown. "blx NewFilePlayerL" -> "movs r0,#0; nop": no tone player,
# Play() returns KErrNotReady, the (silent) key-sound fallback is used and the animation runs.
833a93c4  01f0aaec  0020c046   # startup.exe CStartupTone::ConstructL

# H-phone-ready-skip (TEMPORARY, docs/n95-startup-animation.md §5–6): Startup.exe state 5 waits for
# global state 213 (0xd5, "phone ready") which Phone.exe never publishes yet (its engine does not
# finish on our fake modem). Treat 211 like 213 in Startup's state handler (0x833a8190):
# "cmp r1,#207; bne ret" -> "cmp r1,#211; beq state6". Remove once Phone publishes 0xd5.
833a8198  cf2903d1  d3290cd0   # startup.exe state handler: 211 -> state 6
