# N8 OpenGL ES 2.0: API remoting to the host GPU (design, 2026-11-08)

Why: Symbian^3 games (Angry Birds 2.0: 66 GLES 2.0 functions, shaders) need OpenGL ES 2.0. (OpenGL ES 1.1
then ran in sygl's fixed-function pipeline in the guest; since 2026-11-10 it is remoted the same way:
gles1-host.md.) GLES 2.0 is remoted instead: the guest library
records each call into khr's command buffer (`src/khr/hostgl.cpp`), the syborg-gl device replays it on
the host GPU's own GLES context. GLSL ES 1.00 shaders compile on the host.

## Pieces

| | where | what |
|---|---|---|
| libGLESv2.dll | ROFS1, generated forwarder (`src/khr/gen_khr.py`, SDK `libglesv2u.def`) | `b khr2_<gl name>` into libEGL |
| GL ES 2 front | libEGL.dll (`src/khr/gl2*.c`, partly generated by `tools/gen-gl2.py`) | per-context guest state (bindings, vertex attribute arrays, unpack alignment, element-buffer shadows), name allocation, marshalling, synchronous queries |
| EGL | `src/sygl/egl.c` + `src/khr/eglmux.cpp` | ES 2 configs (`EGL_OPENGL_ES2_BIT`, depth 24, stencil 8), ES 2 contexts (`EGL_CONTEXT_CLIENT_VERSION` 2), the same window surfaces and present path as ES 1 |
| replay | `src/qemu-syborg/hw/arm/syborg_gl2.c` (part generated) | one host EGL context per guest ES 2 context (sharing with the device's context, so surface textures and renderbuffers are visible), name maps, the default framebuffer = the current surface |

## Protocol (syborg_gl_proto.h)

`SYGL_GL2 = 20`: `ctx, fn, args...`, one command per GL call (`fn` = index in the generated function
table). `SYGL_GL2_CURRENT`: `ctx, surf, w, h` (eglMakeCurrent; surf 0 = none). `SYGL_GL2_FREE`: `ctx`.
- Scalars: one word each (floats as their bits).
- Object names: the guest's names (allocated in the guest: glGen*, glCreate*), mapped on the host per
  share group (buffers, textures, renderbuffers, programs, shaders) or per context (framebuffers);
  unknown names are created on first bind (GLES 2 rules). Framebuffer 0 = the current surface's FBO
  in this host context (its colour texture and depth/stencil renderbuffer are the surface's).
- Arrays and data inline, sized in the guest (uniform vectors, buffer data, texture images with the
  unpack alignment, shader sources, attribute names).
- Results: synchronous calls (glGet*, glGetError, info logs, locations, glCheckFramebufferStatus,
  glIs*, glReadPixels, glFinish) flush the batch with an output area; the host writes the result at
  the command's output offset.
- Draws with client vertex arrays: the guest copies each enabled client array's rows (DrawArrays:
  first..first+count; DrawElements: min..max index, from client indices or the guest's shadow of the
  bound element buffer) into the command; the host points the attribute into its copy of the batch.

Orientation: GL ES 2 draws in GL convention (row 0 at the bottom), which is how SYGL_VG_PRESENT and
the composition take EGL window frames. Errors: GL errors come from the host (glGetError syncs).

## Steps

1. EGL ES 2 configs and contexts; libGLESv2 forwarder; the generated marshalling for the simple calls;
   host replay with name maps and the surface FBO; glClear + a shader triangle (test app).
2. Buffers, textures (incl. sub images, compressed), framebuffers/renderbuffers, client arrays.
3. All queries; Angry Birds 2.0 (EGL_RENDERABLE_TYPE ES2, depth 24) as the target.

## Status (2026-11-08)

Steps 1-3 done in one go: all 142 functions marshalled (58 generated, 84 by hand), host replay with
name maps and the surface framebuffer. Angry Birds 2.0 (from its .sisx, `sydb sis install`) asks for
an ES 2 config with depth 24, creates its context and draws its title screen at ~59 fps on the host
GPU. OpenGL ES 1.1 (sygl) runs ZigGLTri and ZigGT2Car (textured 3D) at the apps' 30 fps.

Landscape apps (fixed 2026-11-08). The N8's wsini.ini has `VIRTUALROTATION` with the render stages
`alf compositor platformcompositor`: the display is never rotated (gcebe gets no SetScreenRotation);
screen mode 2 (640x360, 90) is drawn by alf pre-rotated into its portrait surface. Two pieces were
missing:
- **EGL window size**: games call `RWindowBase::FixNativeOrientation()` (Angry Birds imports it); the
  window turns with the screen mode (640x360) but its EGL surface stays in the display's native
  orientation and the app renders rotated itself. Qt's Symbian port says so: "The EGL window surface is
  now fixed to the native orientation of the device, no matter what size we pass when creating it"
  (qapplication_s60.cpp, QTBUG-17742). The phone's EGL glue (eglwindow.dll) sizes surfaces with
  `RWindowBase::SizeForEgl()`; ours (eglos.cpp, plat_n8.cpp) now does too (it was `Size()`: a 640x360
  surface the game filled as if it were 360x640).
- **Layer placement**: such a window's layer keeps its rectangle in the landscape screen (0,0-640,360).
  gcebe maps a rectangle that is outside the panel but inside the turned panel onto the panel, turned
  90 anticlockwise (alf maps its own portrait surface the other way: layer rot 3), and turns the
  content too unless the source is already portrait (native orientation). Layer source rotations
  (slot 7, OpenWF-C: anticlockwise) are now applied by the host composition (SyglLayer fmt bits 8..9).
Angry Birds now fills the panel, turned as on a phone held sideways. Open: taps on its title screen do
nothing yet (it reads advanced pointer events: proximity/pressure; to check what our touch delivers).
Debug aid: `SYBORG_GL_DUMP_LAYERS=DIR` in the QEMU environment writes the layers of the 600th host
composition as PPM files (GL row order).

Logs (2026-11-08): the guest logs each OpenGL ES 2 function's first call per process (`SYGL: GL2
glX: first call`), the first 20 guest-side errors, context creation/current/destruction; sygl's fps
line every 2 s shows when frames stop. `SYBORG_GL2_CHECK=1` in QEMU's environment (e.g. before
`sydb phone`) checks glGetError after every replayed call and writes `syborg-gl: GL2 glX (ctx ...):
GL error 0x...` to qemu.err (debugging only: the app no longer sees those errors). The phone window's
Turn view (Ctrl+T) shows such games upright.

Read-backs (2026-11-08): GLES 2 guarantees glReadPixels only in RGBA/UNSIGNED_BYTE and in the
implementation's read format; the N8's driver also serves GL_RGB, and GTA III (re3) grabs its frame that
way for the menu and loading-screen backgrounds and builds its `models\txd.img` texture cache through
read-backs. The host's Mesa refused (GL_INVALID_OPERATION): striped, sheared garbage. The replay now
reads RGBA8 when the host does not serve the requested format/type and packs RGB, ALPHA, LUMINANCE(_ALPHA),
565, 4444 and 5551 itself (`syborg-gl: GL2 glReadPixels format ... converted`, first 4 in qemu.err).
The guest logs each distinct upload/read shape once (`SYGL: GL2 TexImage2D: ifmt fmt type align WxH`).
A cache built before the fix (re3's `txd.img`/`txd.dir`) has to be deleted; the game rebuilds it.

Framebuffer 0 (2026-11-08): GLES refuses attachment changes on framebuffer 0 (GL_INVALID_OPERATION).
The host's stand-in for 0 is the surface's framebuffer, so a replayed glFramebufferRenderbuffer /
glFramebufferTexture2D there replaced the surface's own attachments: GTA III (re3) detaches "the default
framebuffer's" depth at start-up and then drew without a depth buffer (see-through walls, cars and peds
as a jumble of triangles). Both calls are now refused while the guest has framebuffer 0 bound
(`syborg-gl: GL2 ... on framebuffer 0 ... ignored`, first 4 in qemu.err).

Trace: `SYBORG_GL2_TRACE=FILE` in QEMU's environment; `touch FILE` and the next presented frame's replayed
calls go to qemu.err (`GL2T` lines: call and first words; per draw the first vertices of attribute 0
when it comes from a buffer; once per frame the depth attachment; once per program link status and
attribute locations). FILE is removed after that frame.

Shader precision compatibility (2026-11-09): the saved GTA capture
`capture-1794212509024718203.bin` contradicts the earlier highp assumption: its vertex
shaders declare `precision mediump float;` and form a world-space intermediate before
applying the view transform. At world coordinates around (-540, 1051, 38), rounding one
captured mesh's world positions to binary16 collapses 110 distinct positions to six.
This is an offline numerical demonstration, not proof of the host's executed precision.

Host shader upload now promotes `precision mediump float;` defaults to `highp` when
the host supports highp floats in both stages (checked once; one stage alone would give a
shared uniform two precisions and fail the link). Both vertex and fragment defaults are promoted
so shared uniform/varying precision declarations stay consistent for these shaders.
The bounded token scan preserves source length and line numbers, skips comments, and
leaves integer/sampler defaults, lowp defaults, and explicit qualifiers unchanged.
This is a compatibility policy applied to GLES2 shader uploads, not a transport-byte fix;
it may increase fragment shader cost. `SYBORG_GL2_HIGHP=0` in QEMU's environment restores
the original source for an A/B comparison. The first 16 promoted uploads are logged.
The transport capture retains the original guest shader text; glGetShaderSource queries
return the source supplied to the host compiler, including the promotion.

Owner check 2026-11-10: the GTA III jitter is gone with the promotion (H-gl2-highp, docs/hacks.md).
Validation: source-rewrite tests (including all 16 shaders extracted from the capture)
pass with address/undefined-behaviour sanitizers. Runtime visual confirmation and the
