# Nokia N8 (RM-596): device hacks

The workarounds that belong to this device. Platform-wide ones are in [docs/hacks.md](../../docs/hacks.md).

| Hack | What | Why | Real implementation |
|---|---|---|---|
| **H-gcebe** | `src/gcebe`: our composition backend, a ROM blob at `[composition] blob_addr`; gce.dll's XIP import of compositionbackend.dll ordinal 1 is rebound to it (`composition/gcebe-patches.txt`, generated). Commit and ContentUpdated send the scene's layers to the host (syborg-gl SYGL_COMPOSE): blended and scaled on the GPU, EGL windows' frames taken from the GPU, other surfaces read from guest memory in place, the finished screen written to the display memory. Rotation 0 only; screen 1 (TV-out) composes nothing; without the host GPU it copies layers itself (no blending, no scaling) | the firmware backend drives the Broadcom VideoCore (dispman over VCHI), which the board does not have | rotation, TV-out; presentation without the frame buffer round trip (docs/gpu-host-review.md) |
| surface manager | `surfacemanagerdriver` stand-in = the Symbian Foundation driver (EPL, hardware independent), built from the pinned graphics repo | the firmware's kernel-side copy is dropped with the other kernel-side files | none needed (same control numbers as the firmware's surfacemanager.dll) |
| **H-khr** | `src/khr`: our libEGL.dll and forwarders libOpenVG.dll / libOpenVGU.dll replace Broadcom's forwarders to the VideoCore client (`[[rom.rofs_replace]]` in ROFS1). Since 2026-11-10 (v2, docs/devices/nokia-n8-rm596/egl-vg-host-v2.md) libEGL.dll is a forwarder: every EGL and OpenVG/VGU call is one synchronous SYGL_EGL / SYGL_VG2 command, executed in QEMU by the Khronos RI front end and MiniEGL (src/syvg, libsyvg.a) with its drawing on the host GPU; only the window glue (a surface-manager surface as the window's background, SubmitUpdate after a swap) stays in the guest. Since 2026-11-10 the guest only forwards (docs/devices/nokia-n8-rm596/gles-host.md): OpenGL ES 1.1 and 2 (generated stubs), and the EGL itself (configs: the real phone's 37, contexts, surfaces, strings from the profile) is the host's (src/syvg/syvg_egl.cpp); sygl and eglmux are no longer in libEGL. Host-side RI patches: src/syvg/patches (0001-0013) | the phone's EGL/VG are Broadcom's KHRN client remoting every call to the VideoCore | masks and filters on the host GPU; then a device that speaks KHRN, so Broadcom's own libraries stay |
| **H-khr-egl-n8** | src/syvg patch 0009 (host): our EGL answers as the N8's Broadcom EGL (eglprobe on the owner's phone, docs/real-phone-tracing.md): vendor "Broadcom", version 1.4, SURFACE_TYPE with the swap-preserved and multisample-resolve-box bits, EGL_PRESERVED_RESOURCES refused. alf enables its effect render buffers and preserved swaps only for a vendor starting "Br" (HuiVg10RenderPlugin.cpp ReadAllowsVisualPBufferSurfaces): with "Khronos Group" every transition effect was skipped (2026-11-10). Still no EGL/VG extensions listed (the phone has 14, among them EGL_KHR_image, EGL_NOK_pixmap_type_rsgimage, VG_KHR_EGL_image) | alf's own vendor test (a "temporary check until all HW platforms support feature") | the extensions alf and apps use, implemented and then listed; configs as the phone's (37, RENDERABLE_TYPE 7) |
| **H-khr-pixel-heap** | **Gone with v2** (2026-11-10): image pixels live in QEMU, not in the guest process, so the per-process 128 MB chunk heap (v1 RI patch 0010) is not needed. Kept here for the record of why alf failed: its effect path makes ~17 full-screen render buffers, which did not fit alf's 16 MB heap | - | - |
| **H-gles1-palette-cpu** | `syborg_gl1.h` (QEMU): OES_matrix_palette (vertex skinning) emulated on the host CPU: the host keeps the 32 palette matrices and MATRIX_PALETTE_OES matrix mode; a draw with the palette enabled has its vertices and normals blended into eye space on the host and drawn with an identity modelview (docs/devices/nokia-n8-rm596/gles1-host.md). Limits 32 matrices, 3 units: Broadcom's [inferred] | Mesa's OpenGL ES 1.1 has no OES_matrix_palette | skinning in a vertex shader on the host's ES 3 context (no per-draw CPU work) |
| **H-gles-no-eglimage** | `syborg_gles.h`: glEGLImageTargetTexture2DOES / glEGLImageTargetRenderbufferStorageOES fail with GL_INVALID_OPERATION (ES 1.1 and 2) | the host EGL has no EGL images (eglCreateImageKHR) for any API yet | EGL images in the host EGL (VG images, GL textures, RSgImage pixmaps), then these calls and the EGL extensions (H-egl-extensions) |
| **H-egl-no-pixmap** | `src/syvg/syvg_egl.cpp`: eglCreatePixmapSurface and eglCopyBuffers fail with EGL_BAD_NATIVE_PIXMAP (OpenVG and OpenGL ES) | a native pixmap is a CFbsBitmap: the guest would have to hand its memory (locked) to the host at every sync point | the bitmap's address and layout passed by the guest glue at each sync point; the host converts and writes |
| **H-egl-extensions** | profile `[gl.identity] egl_extensions = ""`: the host EGL lists no extensions | the phone lists 14 (EGL_KHR_image, EGL_KHR_lock_surface, EGL_NOK_*, eglprobe); none is implemented yet, and alf would take paths it cannot finish | implement them on the host, then list the phone's string |
| **H-egl-msaa-gl** | `src/syvg/syvg_egl.cpp`: OpenGL ES surfaces of the phone's 4x configs (EGL_SAMPLES 4) are single-sampled | syborg-gl's GL surfaces have no multisample path yet (OpenVG's have) | the VG multisample framebuffer for GL surfaces too, resolved at swap |
| **H-video-no-decoder** | none (a fact): video playback (Helix, MMF video controller) decodes nothing: the N8 decodes on the VideoCore (vchwdec.vll, ivepolicyserver), which we do not have; ivepolicyserver is killed -19 and the post-processor gets 0 pictures. Assassin's Creed's intro stays black (a tap skips it) | the phone's video decoders are VideoCore firmware | a video decoder device on the host (FFmpeg, as syborg-audio decodes MP3/AAC) behind the decoder interface the phone's MDF plugins use |
| Host scan-out | `syborg_gl.c` frame_store: the composed screen stays on the host (syborg-fb shows it, the frame file carries it to the phone window, screendump reads it); the guest's display memory (HAL EDisplayMemoryAddress) is no longer written | the display memory is the screen surface DSA apps draw into (gcebe composes it as a layer): composing into it fed the output back into the input. Faithful: the phone's display memory is not its scan-out either | fine as is; a guest that reads the screen back through the display memory now sees DSA's picture, not the composition (none known) |
| OES_mapbuffer as a copy | `src/khr/gl1.c`: glMapBufferOES returns a guest copy of the buffer (read from the host), glUnmapBufferOES uploads it | the buffer lives on the host GPU | fine as is (the phone's KHRN client does much the same) |
| eglBindTexImage as a copy | `syborg_gl1.h` gl2_tex_from_surf: the pbuffer's pixels are copied into the bound texture (glCopyTexImage2D) | binding a surface's colour texture into another context's texture object is not possible in GL ES | fine as is (later changes to the pbuffer need another eglBindTexImage, as the spec allows) |
| **H-bt-ondemand** | `[[rom.file_edits]]`: `OnDemand=1` in C32's esock_bt.cmi (generated from the firmware's file), so the ESock Bluetooth worker starts only when a client asks for it | at boot the worker panicked KERN-EXEC 0 (a request on a Bluetooth transport channel it never opened) and C32Start, a system-permanent thread, exited with it | a Bluetooth transport stand-in (HCI over the board's UART, answering "no controller") |
| **H-fmradio-nosession** | code patches: fmradioaudiocontrol.dll's ConstructL does not leave when its FM radio HAL session cannot be made, and its four routing methods return KErrNone at once (the session pointer stays NULL) | the radio HAL server needs the BT/FM combo chip (hciaccess.dll over HCI); its session construction fails (its cleanup then crashes on a null plugin), the control's ConstructL left -2 and the system-permanent AudioServer thread died (Lac.dll links the control statically) | an FM radio HAL stand-in (a radio that reports "no signal"), then these patches go |
| usbaudiodriver stand-in | `src/standins/usbaudiodriver`: channel "USBAudioDrv" opens, controls return KErrNone, requests stay pending | Lac.dll builds its USB audio route while the audio server starts; without the LDD (a firmware kernel-side file) the proxy left -1 and the AudioServer thread died | none needed until USB audio is emulated |
| **H-startuptone-none** | `[[rom.rofs_patches]]`: CenRep 101F8763 key 3 (start-up tone) in our copy of ROFS2 points to `Z:\system\sounds\Wakeup none.aac`, which does not exist | the start-up animation waits for the tone to end; silent RAPIDO audio never ends it, so Startup never left its animation state (UI phase stayed 100, white screen) | a RAPIDO DSP model (as on the 5800) |
| **H-haptics-fail** | `isi-replies.txt`: the haptics request (ISI 1C 9E, hapticsadaptation.dll for EwSrv's FeedbackPlayerThread) gets a failure status (`[10]=1`) | unanswered, every touch feedback waited 3 s (KErrTimedOut, thread killed): app starts and screen changes stalled behind it (start-up 47 s -> 30 s, clock app ~6 s -> ~1 s once answered); an OK reply with an empty Immersion packet froze the UI | a haptics stand-in that speaks the Immersion VIBE packets (the phone would vibrate) |
| RAPIDO DSP ring (aamdaifdriver) | `src/standins/aamdaifdriver`: one 1 MB shared kernel chunk opened in each client process as the "DSP memory" window; MdaifDriver ctl 8 hands each stream its own ring (size from `[[standins]] config = { ring_units = 16 }`, 128 KB regions); Belle (v111, Delight) numbers the controls differently and declares `ctl_map` (Belle:old pairs); F3 0x34 replies paced by a timer (iscpeer ReplyLater) so the audio engine plays silently at about real time (docs/devices/nokia-n8-rm596/rapido-audio.md) | the N8's audio engine writes PCM into the DSP's shared memory; with no ring size it wrote past any buffer and !AudioProcessingEngine died (KERN-EXEC 3) | a DSP model that plays the rings to the host's audio (then the start-up tone and H-startuptone-none go) |
| alignment checking off | kernel variant syborgfx built `--unaligned` (tools/baseport_variant.py: ARM1176 InitialMMUCR without MMUCR_A) | Nokia's Symbian^3 code loads unaligned words (mdccommon.dll, Thumb `ldr`): the thumbnail server crash-looped, apps showing media failed. Faithful: the phone's own kernel must allow them | fine as is (matches the device) |
| **H-delight-own-drivers** | Delight 6.7 only (`models/nokia-n8-rm596/firmware/111.040.1511~delight-6.7`): `[[rom.rofs_replace]] standin = "lightpdd.pdd"` puts our LightPdd stand-in in place of the `sys/bin/lightpdd.pdd` that Delight added to ROFS1 | on the composite Z: a ROFS file shadows the core image's file of the same name, so Delight's real-hardware PDD was loaded instead of ours; LoadPhysicalDevice("LightPdd") failed, the lights adaptation left -5 and lightsaserver (system-permanent) took the kernel down (KERN 102 at 4.4 s). Delight's ROFS1 also adds patcherS3.ldd, MemSpyDriver.ldd, wlanpdd.pdd (not loaded at boot so far) | none needed: our stand-in is the device model for that driver |
